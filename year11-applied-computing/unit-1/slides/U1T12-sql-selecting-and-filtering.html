Key knowledge

Four clauses, always in this order

ClauseMeansOptional?
SELECTWhich columns to showNo
FROMWhich table to readNo
WHEREWhich rows to keepYes
ORDER BYHow to sort what is leftYes

SQL reads like English and executes in a different order — FROM first, then WHERE, then SELECT. Knowing that explains most confusing error messages.

The basics

Every column, then the ones you want

SELECT * FROM station;

The * means every column. Useful while exploring, poor practice in a finished solution — it breaks the moment somebody adds a column.

SELECT station_name, elevation_m FROM station;

Naming your columns is a non-functional requirement in disguise: it makes the query readable and stops it changing meaning later.

Filtering

Keeping only the rows you want

SELECT station_name, elevation_m
FROM station
WHERE elevation_m > 75;

Combining conditions

AND narrows, OR widens

SELECT obs_date, max_temp_c
FROM observation
WHERE station_id = 76031 AND max_temp_c > 40;

The trap

WHERE a = 1 OR a = 2 AND b = 3 does not mean what it looks like — AND binds tighter than OR. Use brackets whenever you mix them, every time, without thinking about it.

Sorting

Ascending unless you say otherwise

SELECT obs_date, max_temp_c
FROM observation
WHERE station_id = 76031
ORDER BY max_temp_c DESC
LIMIT 5;

ASC is the default and is usually left off. DESC reverses it. LIMIT caps how many rows come back — essential when a table has 2190 of them.

Worked example

I do “The wettest days at Cape Otway”

  1. 1 Which table? Rainfall is daily, so observation.
  2. 2 Which rows? Cape Otway is station 90015. That is my WHERE.
  3. 3 Which columns? The date and the rainfall.
  4. 4 Wettest means sort by rainfall, descending, and cap it.
  5. ✓ SELECT obs_date, rainfall_mm
    FROM observation
    WHERE station_id = 90015
    ORDER BY rainfall_mm DESC
    LIMIT 10;
The order I worked in

Table, then rows, then columns, then sort. That is the execution order, not the writing order, and building a query that way is far more reliable than typing left to right.

Together

We do What condition does this need?

1. Observations where no rainfall was recorded at all

WHERE rainfall_mm IS NULL — not = 0, which means a dry day

2. Winter observations only

WHERE obs_date BETWEEN '2025-06-01' AND '2025-08-31'

3. Stations whose name ends in Airport

WHERE station_name LIKE '%Airport'

Number 1 is the important one

NULL means we do not know. Zero means we know it was zero. Our raw extract has 42 of the first kind.
