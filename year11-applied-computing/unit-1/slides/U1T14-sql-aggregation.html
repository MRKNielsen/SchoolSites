The distinction worth getting right now

WHERE filters rows, before grouping. HAVING filters groups, after. Swapping them is the most common mistake in this topic.

Key knowledge

Five functions that collapse many rows into one

FunctionReturnsDescriptive statistic
COUNT(*)How many rowsCount / frequency
AVG(col)The meanAverage
SUM(col)The total—
MIN(col)The smallest—
MAX(col)The largest—

SELECT COUNT(*), ROUND(AVG(max_temp_c),1), MAX(max_temp_c)
FROM observation;

SQLite has no built-in median or standard deviation. Those two you do in the spreadsheet — which is Topic 15.

Key knowledge

One answer per group instead of one overall

SELECT station_id, COUNT(*) AS days, ROUND(AVG(max_temp_c),1) AS mean_max
FROM observation
GROUP BY station_id
ORDER BY mean_max DESC;

Without GROUP BY you get one row for the whole table. With it, you get one row per distinct value of the grouping column.

The rule that catches everyone

Every column in SELECT must either be in the GROUP BY or inside an aggregate function. Anything else is a question with no single answer.

Key knowledge

Filtering the groups, not the rows

SELECT station_id, COUNT(*) AS wet_days
FROM observation
WHERE rainfall_mm > 0
GROUP BY station_id
HAVING COUNT(*) > 100
ORDER BY wet_days DESC;

ClauseFiltersRuns
WHERE rainfall_mm > 0Individual rowsBefore grouping
HAVING COUNT(*) > 100Whole groupsAfter grouping

You cannot put COUNT(*) in a WHERE — at that point the groups do not exist yet.

Worked example

I do “Mean maximum by region, busiest first”

  1. 1 Region names mean joining through station. Two joins.
  2. 2 One row per region, so GROUP BY r.region_name.
  3. 3 I want the count and the mean, rounded to one decimal.
  4. 4 Only regions with a full year of data, so HAVING COUNT(*) > 300.
  5. ✓ SELECT r.region_name, COUNT(*) AS obs, ROUND(AVG(o.max_temp_c),1) AS mean_max
    FROM observation o
    JOIN station s ON s.station_id = o.station_id
    JOIN region r ON r.region_id = s.region_id
    GROUP BY r.region_name
    HAVING COUNT(*) > 300
    ORDER BY mean_max DESC;
The order to write it in

FROM and JOIN, then WHERE, then GROUP BY, then HAVING, then SELECT, then ORDER BY.

That is the order SQL executes in, and writing in that order makes the query come out right first time far more often.
