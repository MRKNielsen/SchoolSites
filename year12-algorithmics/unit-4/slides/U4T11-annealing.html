Simulated Annealing

Unit 4 AOS2 · Topic 11 of 17 — going downhill on purpose

VCE Algorithmics (HESS) · Northcote High School

The problem it solves

Hill climbing stops at the first peak. To reach a higher one, you must first walk downhill — and hill climbing will never do that.

  • The fix is structural: sometimes accept a worse solution, so the search can leave a local optimum.
  • But if you accept worse moves too freely, you never settle anywhere — the search becomes a random walk.
  • So the willingness to accept worse moves must decrease over time.
The metaphor

Annealing in metallurgy: heat metal so its atoms move freely, then cool it slowly so they settle into a low-energy, well-ordered structure. Cool too fast and you freeze in defects.

The algorithm

High-level pseudocode

Generate initial candidate solution S
Set initial temperature T
Repeat until terminating condition:
  Generate a neighbour S_new of S
  If S_new is better Do S ← S_new
  Else Do S ← S_new with probability p(ΔE, T)
  Decrease T
Return best S seen

  • Everything from Topic 10 still applies: representation, neighbourhood, objective.
  • Two new parameters: the temperature \(T\) and the cooling schedule that reduces it.

The acceptance rule

How a candidate is accepted

If the new candidate is better, accept it always.
If it is worse by amount \(\Delta E\), accept it with probability \(p = e^{-\Delta E / T}\).

  • Bigger \(\Delta E\) → smaller \(p\). Slightly worse moves are accepted readily; drastically worse ones almost never.
  • Higher \(T\) → larger \(p\). Early on, the search roams freely; later, it becomes fussy.
  • As \(T \to 0\), \(p \to 0\) and the algorithm degenerates into ordinary hill climbing — which is exactly what you want at the end.
You are not asked to compute it

The exam expects you to explain the rule — that acceptance depends on how much worse the candidate is and on the current temperature — not to evaluate exponentials.

The cooling schedule

  • Too fast: the search freezes early, behaving like hill climbing, and gets stuck in whatever local optimum it happened to be near.
  • Too slow: the search keeps accepting bad moves and wanders; it wastes time and may never converge within the budget.
  • A common schedule is geometric: \(T \leftarrow \alpha T\) with \(\alpha\) around 0.95 — a small constant fraction removed each step.
The trade-off in one line

Cooling speed controls the balance between exploration (roaming widely) and exploitation (refining what you have).

Terminating conditions

The pseudocode says "repeat until a terminating condition is reached". Any of these is acceptable:

  • The temperature has fallen below a set threshold.
  • A fixed number of iterations has been performed.
  • No improvement has been found for a set number of consecutive iterations.
  • A time budget has expired, or a solution meeting a target quality has been found.
What is not acceptable

"Until the optimal solution is found." You cannot recognise the optimum without solving the problem exactly — which is the thing you were avoiding.

Return the best, not the last

Because worse moves are sometimes accepted, the final solution may not be the best one visited. A correct implementation records the best-so-far separately and returns that.

Exam focus

Explain how a candidate is accepted

Adapted from VCAA Algorithmics (HESS) Written Examination 2021, Section B Q8c(i)–(iii)

Question

A simulated annealing algorithm is applied to the travelling salesman problem, using a greedy tour as its initial candidate.

i. Explain how the algorithm would determine whether a new candidate solution is accepted. (3 marks)

ii. State a terminating condition that could be used. (1 mark)

iii. Describe one advantage and one limitation of using simulated annealing for TSP. (2 marks)

Working it through

  1. 1 i — the improving case. Compute the new tour's total length. If it is shorter than the current tour, accept it unconditionally.
  2. 2 i — the worsening case. If it is longer, accept it with a probability that depends on how much longer it is and on the current temperature: small increases and high temperatures make acceptance likely.
  3. 3 i — the mechanism. Compute that probability, draw a random number, and accept if the number falls below it. As temperature falls, such acceptances become rare.
  4. 4 ii. "Stop when the temperature drops below a fixed threshold" — or a fixed iteration count, or no improvement for \(k\) iterations.
  5. 5 iii — advantage. It can escape local optima that trap hill climbing, so it generally finds better tours; and it runs in reasonable time on instances where exact methods are infeasible.
  6. ✓ iii — limitation. It gives no guarantee of optimality and no bound on how far off it is; results vary between runs, and it needs parameter tuning.

Diagnose the implementation

Adapted from VCAA Algorithmics (HESS) Written Examination 2022, Section B Q12c(ii)

Question (1 mark)

A student has correctly implemented the simulated annealing algorithm, but finds that it only ever accepts candidate solutions that are improvements on the current solution.

Describe how she could modify the parameters of the algorithm to correct this.

Response

The initial temperature is too low (or the cooling is too rapid), so the acceptance probability for a worsening move is effectively zero from the outset and the algorithm behaves as pure hill climbing. She should raise the initial temperature, and slow the cooling schedule, so that early in the search worse candidates are accepted with meaningful probability.

Note what the question rules out

It says the implementation is correct and asks about parameters. So "there's a bug in the acceptance test" is not the expected answer — the diagnosis must be about \(T\) and the schedule.

Elaboration — reading the symptom backwards

That question is a small piece of diagnostic reasoning, and the method generalises.

The underlying question

Every one of these asks the same thing: is the search exploring too much or too little? Temperature is the dial that sets the balance, and cooling is how fast the dial turns.

Check yourself

Why does simulated annealing accept worse solutions at all?

To escape local optima. Reaching a better peak often requires first moving downhill, and an algorithm that only accepts improvements can never do so. Accepting worse moves lets the search cross a valley to a higher region.

What happens as the temperature approaches zero, and why is that desirable?

The probability of accepting a worsening move approaches zero, so the algorithm becomes ordinary hill climbing. That is desirable at the end: early exploration finds a promising region, and late exploitation refines the best solution within it rather than wandering away.

Why must the algorithm return the best solution seen, not the current one?

Because worsening moves are sometimes accepted, the current solution at termination may be worse than one visited earlier. Recording the best-so-far separately guarantees the returned answer is at least as good as everything examined.

Give a valid terminating condition, and one that is not valid.

Valid: temperature below a threshold; a fixed iteration count; no improvement for \(k\) iterations; a time budget. Not valid: "stop when the optimal solution is found" — recognising the optimum would require solving the problem exactly, which is what the heuristic exists to avoid.
