Graph Algorithm Complexity

Unit 4 AOS1 · Topic 4 of 6 — the Unit 3 algorithms, now with their reasons attached

VCE Algorithmics (HESS) · Northcote High School

Input size for graphs: two numbers, not one

Every complexity claim so far had a single \(n\). Graphs break that.

  • A graph has \(|V|\) nodes and \(|E|\) edges. Both can vary independently, so bounds are written in terms of both.
  • Sparse: \(|E|\) is close to \(|V|\) — a road network, a family tree.
  • Dense: \(|E|\) is close to \(|V|^2\) — a fully-connected distance matrix.
The range that matters

For a simple connected graph, \(|V| - 1 \le |E| \le \dfrac{|V|(|V|-1)}{2}\). So \(|E|\) can be as small as \(\Theta(|V|)\) or as large as \(\Theta(|V|^2)\) — a whole growth class of difference.

Consequence

\(O(|V| + |E|)\) and \(O(|V| \times |E|)\) are wildly different claims. Collapsing both to "\(O(n)\)" throws away the entire question.

  • A sum is dominated by its larger term — so \(O(|V|+|E|)\) means "one pass over the whole graph", which is the best you can hope for.
  • A product means "for every node, walk every edge" — a nested traversal, and usually a sign something can be improved.
Reading a bound out loud

\(O(|V| + |E|)\): "touches each node and each edge a constant number of times." If your description of an algorithm doesn't match that sentence, the bound is probably wrong.

BFS and DFS: \(O(|V| + |E|)\)

  1. 1 Each node is enqueued and dequeued at most once, because of the visited set — \(O(|V|)\) across the whole run.
  2. 2 When a node is dequeued, we walk its adjacency list once.
  3. 3 Summing those walks over all nodes counts each edge exactly twice in an undirected graph (once from each end) — \(O(|E|)\) in total, not \(O(|E|)\) each.
  4. ✓ Total \(O(|V| + |E|)\).
This is amortised reasoning

Step 3 is the move that matters. We did not say "each of \(|V|\) nodes walks up to \(|E|\) edges, so \(|V|\times|E|\)". We added the walks up and found the total is \(|E|\). Getting this wrong is the classic error.

The classic trap: multiplying instead of amortising

Wrong

"BFS visits \(|V|\) nodes, and at each node examines up to \(|E|\) edges, so it is \(O(|V| \times |E|)\)."

Right

"BFS visits each node once and each edge a constant number of times overall, so the total is \(O(|V| + |E|)\)."

  • The wrong version double-counts: it charges every node the whole edge set, when the edge sets partition.
  • \(\sum_{v} \deg(v) = 2|E|\) — the handshaking lemma. That single identity is the justification.
Spot the difference in your own writing

If you find yourself multiplying two input-size parameters, stop and ask whether the inner quantity sums to something smaller across the outer loop. Very often it does.

Dijkstra with a binary heap

  1. 1 Each node is extracted from the priority queue once. Each extraction costs \(O(\log |V|)\) — total \(O(|V|\log|V|)\).
  2. 2 Each edge may trigger one decrease-key / insert, costing \(O(\log |V|)\) — total \(O(|E|\log|V|)\).
  3. 3 Add them: \(O((|V| + |E|)\log|V|)\), usually written \(O(|E|\log|V|)\) for a connected graph where \(|E| \ge |V| - 1\).
Where the log comes from

Entirely from the data structure. With an unsorted array instead of a heap, extract-min is \(O(|V|)\) and Dijkstra becomes \(O(|V|^2)\) — which is actually faster on dense graphs. Same algorithm, different structure, different bound.

A property question

Dijkstra requires non-negative edge weights. With a negative edge it can finalise a node too early and return a wrong distance — a favourite exam question, and not a complexity issue at all.

Prim's, Floyd–Warshall, PageRank

AlgorithmBoundThe one-line justification
Prim's (binary heap)\(O(|E|\log|V|)\)same skeleton as Dijkstra — extract each node once, relax each edge once
Kruskal's\(O(|E|\log|E|)\)dominated by sorting the edges

Note the \(\Theta\) on Floyd–Warshall

Its loops run to completion regardless of the graph — no early exit, no data dependence. Best and worst case coincide, so \(\Theta\) is honest here where it would not be for BFS.

Exam focus

Which bound, when there are two sizes?

Adapted from VCAA Algorithmics (HESS) Written Examination 2021, Section A Q18

Setup

A network is stored as a dictionary links, where each key is one of \(v\) nodes and each value is a list of that node's outgoing links. There are \(e\) links in total across the whole structure.

An algorithm iterates over every node and, for each, counts how many of its outgoing links exceed a given weight.

The time complexity of this algorithm is — which one?

A\(O(v)\)
B\(O(e)\)
C\(O(v + e)\)
D\(O(v \times e)\)

Working it through

  1. 1 The outer work: we touch each of the \(v\) nodes once — \(O(v)\) even before looking at any links.
  2. 2 The inner work: for a single node we walk its own list. That is not \(e\) — it is that node's share of \(e\).
  3. 3 Sum the inner work: across all nodes, the lists partition the link set, so the walks total exactly \(e\) steps.
  4. 4 Combine: \(O(v) + O(e) = O(v + e)\).
  5. ✓ Answer: C.
Why each distractor is wrong

A ignores the link-walking entirely. B forgets that we pay \(O(v)\) just to visit the nodes — which matters if many nodes have no links. D is the amortisation trap from two slides back: it charges every node the whole link set.

Elaboration — when the answer really is a product

Option D is not always wrong. It is wrong here because the inner lists partition. Change that and the product returns.

A genuine product

"For each node \(u\), run a full BFS from \(u\)." Each BFS is \(O(v+e)\) and there are \(v\) of them → \(O(v(v+e))\). Here the inner work does not partition — every BFS re-traverses the whole graph.

The test to apply

Ask: across the whole run, is each edge examined a constant number of times, or once per outer iteration? Constant → add. Once per iteration → multiply.

Check it

Which is Floyd–Warshall? (Neither, quite — it examines every node triple, so it is \(\Theta(|V|^3)\) regardless of \(|E|\). Some algorithms don't care about the edge count at all.)

Check yourself

Justify \(O(|V|+|E|)\) for BFS in two sentences.

Each node is enqueued and dequeued at most once because of the visited set, contributing \(O(|V|)\). Each node's adjacency list is walked once when it is dequeued, and those lists together contain \(2|E|\) entries, contributing \(O(|E|)\).

On a dense graph, which Dijkstra implementation is faster and why?

The array version, \(O(|V|^2)\). On a dense graph \(|E| \approx |V|^2\), so the heap version is \(O(|V|^2\log|V|)\) — a whole log factor worse. The heap only pays off when the graph is sparse.

Why is Floyd–Warshall \(\Theta\) rather than just \(O\)?

Its three loops always run to completion — there is no early exit and no dependence on the graph's shape. Best and worst case are identical, so the bound is tight from both sides.

An algorithm runs BFS from every node. Complexity, and why isn't it \(O(|V|+|E|)\)?

\(O(|V|(|V|+|E|))\). The edge walks do not partition here — each of the \(|V|\) separate BFS runs traverses the entire graph independently, so the costs multiply rather than sum.

One sentence to remember

Graphs have two size parameters; add when the inner work partitions across the outer loop, multiply only when it genuinely repeats.
