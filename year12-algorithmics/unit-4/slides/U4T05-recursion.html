Call Graphs and Recursion

Unit 4 AOS1 · Topic 5 of 6 — turning a recursive shape into an equation

VCE Algorithmics (HESS) · Northcote High School

Why loops-and-bodies isn't enough

Topic 3's method assumed you could see how many times each loop runs. A recursive algorithm has no loop to look at.

Where does the work go?

Algorithm F(n):
  If n ≤ 1 Do Return 1
  Return F(n-1) + F(n-2)

  • Each call does \(O(1)\) of its own work — one comparison, one addition.
  • But it spawns two more calls, which each spawn two more…
  • The cost is not in any one call. It is in how many calls happen.
The new question

For recursion, complexity analysis becomes: how many calls are made, and what does each cost? The call graph answers the first.

A call graph shows who calls whom

  • One node per invocation, labelled with its argument.
  • An edge from a call to each call it makes.
  • The depth is how far the recursion nests before hitting a base case.
  • The total number of nodes is the number of calls — and hence, times the per-call cost, the running time.
Draw it small

Sketch \(n = 4\) or \(5\) by hand. The shape is visible at small \(n\), and the shape is what generalises.

F(3) appears twice, F(2) three times — already.

Shape 1 — branching recursion explodes

  • Naive Fibonacci makes two calls per invocation, each on a problem barely smaller than the original.
  • Level 0 has 1 call, level 1 has 2, level 2 has 4 … the tree roughly doubles each level.
  • Depth is about \(n\), so the number of calls is roughly \(2^n\) — precisely, \(\Theta(\phi^n)\) where \(\phi \approx 1.618\).
The reason it is catastrophic

Not the branching alone — the repeated work. \(F(3)\) is recomputed from scratch every time it appears. At \(n = 40\) that is over 100 million calls to compute 40 numbers.

The fix, named

Store each result the first time you compute it — memoisation. It collapses \(\Theta(\phi^n)\) to \(\Theta(n)\), because each of the \(n\) subproblems is now solved once. You will meet this again as dynamic programming in AOS2.

Shape 2 — halving recursion is friendly

  • Merge sort makes two calls, but each on a problem of half the size.
  • Level 0: one problem of size \(n\). Level 1: two of size \(n/2\). Level 2: four of \(n/4\).
  • Work per level stays \(n\) — the pieces get smaller exactly as fast as they get more numerous.
  • Number of levels: \(\log_2 n\), because that is how many halvings reach size 1.
Total

\(n\) work per level \(\times\) \(\log_2 n\) levels \(= \Theta(n\log n)\).

The contrast in one line

Fibonacci: \(n \to n-1\) and \(n-2\). Merge sort: \(n \to n/2\) twice. Subtracting gives depth \(n\); dividing gives depth \(\log n\). That difference is everything.

From code to equation

A recurrence relation

An equation defining \(T(n)\) — the cost on input size \(n\) — in terms of \(T\) of smaller sizes, plus the work done outside the recursive calls.

  1. 1 How many recursive calls? That is the coefficient \(a\).
  2. 2 On what size? \(n/b\) if divided, \(n-k\) if reduced.
  3. 3 What non-recursive work? The splitting, combining, looping — call it \(f(n)\).
  4. 4 Assemble: \(T(n) = a\,T(n/b) + f(n)\), plus a base case \(T(1) = O(1)\).
Never omit the base case

A recurrence without one defines nothing. Exam questions have asked directly for the missing base case of a described process.

Worked example — merge sort's recurrence

Algorithm

Algorithm mergeSort(L):
  If |L| ≤ 1 Do Return L
  split L into A, B at the midpoint
  A ← mergeSort(A)
  B ← mergeSort(B)
  Return merge(A, B)

  1. 1 Calls: two → \(a = 2\).
  2. 2 Size: half each → \(b = 2\).
  3. 3 Other work: the split is \(O(n)\) and merge compares each element once, \(O(n)\). So \(f(n) = O(n)\).
  4. 4 Base case: \(|L| \le 1\), cost \(O(1)\).
  5. ✓ \(T(n) = 2T(n/2) + O(n)\), \(\;T(1) = O(1)\).
Justifying \(f(n)\) is where marks live

"The merge is \(O(n)\) because each of the \(n\) elements is placed into the output exactly once." The clause after "because" is the mark.

Exam focus

Explain why the recurrence takes this form

Adapted from VCAA Algorithmics (HESS) Written Examination 2023, Section B Q7b(i)

Question (1 mark)

A sorting machine organises a bag of \(n\) balls by diameter. It reads each ball's diameter in constant time and distributes the balls into three bags, then organises each bag by the same process.

Assume that each time the machine distributes balls it produces three bags holding a similar number of balls. Let \(S(n)\) be the time complexity of organising a bag of \(n\) balls.

Explain why \(S(n) = 3S(n/3) + O(n)\) for \(n > 1\).

Before you read on

Three numbers appear in that equation. Account for each one separately — that is the structure of the answer.

Working it through

  1. 1 The 3 in front: the machine produces three bags and organises each of them, so the recursive process happens three times.
  2. 2 The \(n/3\) inside: we are told the three bags hold a similar number of balls, so each holds about \(n/3\) of them.
  3. 3 The \(O(n)\) term: to distribute the balls, the machine reads every ball's diameter once. Each read is constant time and there are \(n\) balls, so distributing costs \(O(n)\) — and this work is outside the recursion.
  4. ✓ Adding the recursive cost to the distribution cost gives \(S(n) = 3S(n/3) + O(n)\).
The shape of a 1-mark "explain" answer

One sentence per component, each tying a number in the equation to a physical fact in the scenario. Restating the equation in words earns nothing.

The contrast — when the bags don't split evenly

Adapted from VCAA Algorithmics (HESS) Written Examination 2023, Section B Q7c(i)

Question (1 mark)

Now consider the case where every distribution puts all the balls into a single bag, apart from the two used as reference points. Let \(T(n)\) be the time complexity in this case.

Explain why \(T(n) = T(n-2) + O(n)\) for \(n > 1\).

Response

Only one bag needs organising, so there is a single recursive call — hence the coefficient 1. That bag holds all but the two reference balls, so its size is \(n - 2\), not \(n/3\). The distribution step still reads every ball once, so the non-recursive work remains \(O(n)\).

Why this pairing is set

Same machine, same code — a different input produces a completely different recurrence. This is the best/worst-case distinction from Topic 2, now in recursive form.

Elaboration — read the recurrence's shape

Before solving anything, you can predict the answer from the form alone.

FormDepthReasonTypical result
\(T(n/b) + \ldots\)\(\log_b n\)dividing shrinks fast\(\log n\), \(n\), \(n\log n\)
\(T(n-k) + \ldots\)\(n/k\)subtracting shrinks slowly\(n\), \(n^2\)
\(2T(n-1) + \ldots\)\(n\)branching and subtracting\(2^n\)
  • \(T(n) = T(n-2) + O(n)\): depth \(n/2\), each level costing up to \(O(n)\) → \(O(n^2)\).
  • \(S(n) = 3S(n/3) + O(n)\): depth \(\log_3 n\), \(O(n)\) work per level → \(O(n\log n)\).
A useful sanity check

If your solved answer disagrees with the shape prediction, you have made an arithmetic slip. Topic 6 makes both of these precise.

Check yourself

Write the recurrence for binary search on a sorted list of length \(n\).

\(T(n) = T(n/2) + O(1)\), with \(T(1) = O(1)\). One recursive call (we discard half and recurse on the other), on half the size, with constant work to compare against the midpoint.

Why is naive Fibonacci exponential when it only makes two calls, the same as merge sort?

Because of how the size shrinks. Merge sort halves (\(n \to n/2\)), giving depth \(\log n\); Fibonacci subtracts (\(n \to n-1\)), giving depth \(n\). Two branches over depth \(n\) is \(2^n\) nodes; two branches over depth \(\log n\) is only \(n\).

What does memoisation change about the call graph?

It collapses repeated subtrees. Each distinct argument is computed once and stored; later calls with the same argument return immediately. The graph goes from an exponentially large tree to one node per distinct subproblem — \(\Theta(n)\) for Fibonacci.

An algorithm makes 4 recursive calls on inputs of size \(n/2\), with \(O(n^2)\) work outside. Recurrence?

\(T(n) = 4T(n/2) + O(n^2)\). Read straight off: \(a = 4\) calls, \(b = 2\) division factor, \(f(n) = n^2\) non-recursive work. Topic 6 will show this one solves to \(\Theta(n^2\log n)\).
