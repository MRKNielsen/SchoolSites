Θ, Ω, and Which Input

Unit 4 AOS1 · Topic 2 of 6 — two independent questions people constantly merge

VCE Algorithmics (HESS) · Northcote High School

Two questions, not one

Almost every mistake in this topic comes from collapsing two separate choices into one.

Question 1 — which bound?Question 2 — which input?
\(O\) — at most thisBest case — the friendliest input of size \(n\)
\(\Omega\) — at least thisAverage case — over some distribution of inputs
\(\Theta\) — exactly this, up to constantsWorst case — the nastiest input of size \(n\)
They are independent

You can ask for an upper bound on the best case, or a lower bound on the worst case, or a tight bound on the average. Nine combinations, all meaningful. \(O\) does not mean "worst case".

\(\Omega\) and \(\Theta\), formally

Omega — lower bound

\(f(n) = \Omega(g(n))\) if there exist \(c > 0\), \(n_0\) with \(f(n) \ge c\,g(n)\) for all \(n \ge n_0\).

Theta — tight bound

\(f(n) = \Theta(g(n))\) if \(f(n) = O(g(n))\) and \(f(n) = \Omega(g(n))\).

  • \(\Theta\) is the strong statement: the growth is pinned, sandwiched between two multiples of \(g\).
  • If you can prove \(\Theta\), say \(\Theta\) — it carries strictly more information than \(O\).
  • \(3n^2 + 5n = \Theta(n^2)\), but \(3n^2 + 5n\) is only \(O(n^3)\), never \(\Theta(n^3)\).

The sandwich, drawn

  • Beyond \(n_0\), \(f\) is trapped between \(c_1 g\) and \(c_2 g\).
  • Both multiples are of the same \(g\) — that is what makes the bound tight.
  • Note there are now two constants to exhibit, not one.
Sanity check

If you cannot draw a lower curve of the same shape underneath \(f\), you do not have \(\Theta\) — you have \(O\) and should say so.

Best, average, worst — three questions about one algorithm

Fix the input size at \(n\). There are still many inputs of that size, and the algorithm may do different amounts of work on each.

  • Best case: the minimum work over all inputs of size \(n\). Usually of limited practical interest — it tells you what happens when you get lucky.
  • Worst case: the maximum. This is a guarantee: the algorithm will never do worse.
  • Average case: the mean over a stated distribution of inputs. The phrase "stated distribution" is doing real work — an average is meaningless without it.
The subtle one

Average case is not "halfway between best and worst". For linear search on a random target that is present, the average is about \(n/2\) comparisons — which happens to be \(\Theta(n)\), the same class as the worst case.

Why we default to worst case

  1. 1 It is a guarantee. "Never worse than this" is a promise you can build a system on. "Sometimes this good" is not.
  2. 2 It needs no assumptions. Average case requires you to know the input distribution. In practice you rarely do, and real data is not random.
  3. 3 The worst case often happens. Sorted or nearly-sorted data is extremely common — and it is exactly the worst case for naive quicksort.
  4. 4 Adversaries exist. If an attacker chooses your input, the worst case is not unlucky; it is the design brief.
But say which you mean

If a question does not specify, state your assumption: "assuming worst case…". It costs one clause and protects the mark.

Worked example — linear search, all three cases

Algorithm

Algorithm find(L, v):
  For i ← 1 to n Do
    If L[i] = v Do
      Return i
  Return NotFound

  1. 1 Best: \(v\) sits at \(L[1]\). One comparison. \(\Theta(1)\).
  2. 2 Worst: \(v\) is at \(L[n]\), or absent entirely. \(n\) comparisons. \(\Theta(n)\).
  3. 3 Average (present, uniformly at random): \(\frac{1+2+\cdots+n}{n} = \frac{n+1}{2}\) comparisons — \(\Theta(n)\).
  4. ✓ Best differs in class; average and worst do not.
Naming the witness

Notice each case came with a specific input. Exam questions frequently ask for exactly that — not just the bound, but an input that achieves it.

Worked example — early-exit bubble sort

The variant

Standard bubble sort, plus: if a full pass makes no swaps, stop immediately.

  1. 1 Best case input: already sorted ascending. The first pass makes no swaps, so the algorithm exits after \(n-1\) comparisons. \(\Theta(n)\).
  2. 2 Worst case input: sorted descending. Every element must travel the full length; \(n-1\) passes of up to \(n-1\) comparisons. \(\Theta(n^2)\).
  3. 3 So: best \(\Theta(n)\), worst \(\Theta(n^2)\). The early exit changed the best case and did nothing at all to the worst.
  4. ✓ Overall we may say the algorithm is \(O(n^2)\) and \(\Omega(n)\) — but not \(\Theta\) of anything, because the two ends differ.
The insight worth carrying

An optimisation that improves the best case and leaves the worst case alone has not improved the guarantee. Marketing loves such optimisations.

When \(\Theta\) does not exist

Early-exit bubble sort has no single \(\Theta\) across all inputs. This is not a failure of analysis — it is information.

  • You can write \(\Theta\) once you fix the case: worst case is \(\Theta(n^2)\); best case is \(\Theta(n)\). Both are precise.
  • What you cannot write is "bubble sort is \(\Theta(n^2)\)" unqualified, because the best case escapes that bound from below.
  • Merge sort, by contrast, does \(\Theta(n\log n)\) work on every input — so "merge sort is \(\Theta(n\log n)\)" is legitimate without qualification.
A good habit

Write the case and the bound together: "worst case \(\Theta(n^2)\)". It is four words and it is always unambiguous.

Exam focus

State the case — and name an input that achieves it

Adapted from VCAA Algorithmics (HESS) Written Examination 2022, Section B Q8a–b

Question (4 marks)

An algorithm searches a list List of length \(n\) for a value Value by repeatedly splitting the list into a left part, a middle item and a right part. The split operation runs in time proportional to the length of the list it is given.

a. State the worst case time complexity in terms of \(n\), and give an example of an input Value and List, with \(n \ge 5\), that produces this worst case. (2 marks)

b. State the best case time complexity, and describe the relationship between Value and the elements of List for that best case to occur. (2 marks)

Note the verb

"State" gets you the bound. The second mark in each part is for the input — a concrete list, or a precise condition. Answers that stop at the bound score half.

Working it through

  1. 1 What does one split cost? Proportional to the current list length — so \(O(k)\) on a list of length \(k\). It is not constant. That is the whole question.
  2. 2 Worst case shape: the target is never the middle item, and the search keeps recursing until the list is exhausted — \(n\) splits, on lists of length \(n, n-1, \ldots\)
  3. 3 Sum the splits: \(n + (n-1) + \cdots + 1 = \tfrac{n(n+1)}{2}\), so worst case \(\Theta(n^2)\).
  4. 4 Name a witness: List = [1,2,3,4,5], Value = 99 — absent, so every split happens.
  5. 5 Best case: the very first split puts Value in the middle position. One split, cost \(\Theta(n)\).
  6. ✓ Best \(\Theta(n)\) — not \(\Theta(1)\), because that single split still touches the whole list.

Elaboration — the trap in the best case

The tempting wrong answer

"Best case is \(\Theta(1)\) — we find it immediately."

  • Finding it immediately means one split, not zero work. And the split itself is linear in the list length.
  • So the floor on the best case is set by the cost of a single operation on the full input, \(\Theta(n)\).
  • General principle: the best case can never be cheaper than the cheapest thing the algorithm must do at least once. If the algorithm must read the whole input, no case is better than \(\Omega(n)\).
Apply it

What is the best case for "find the maximum of an unsorted list"? (\(\Theta(n)\) — you cannot know the maximum without looking at every element, no matter how lucky you are.)

A second exam item — quicksort's worst case

Adapted from VCAA Algorithmics (HESS) Written Examination 2023, Section A Q14

Quicksort on a list already sorted in descending order hits its worst case… — when?

Aonly if the first item is the pivot each time
Bonly if the last item is the pivot each time
Cif either the first or the last item is the pivot each time
Dwhen the pivot is chosen at random
Reasoning

On a fully sorted list (either direction), the first and last items are the extremes. Picking either as pivot puts everything on one side — partitions of size \(n-1\) and \(0\), giving \(n\) levels of recursion and \(\Theta(n^2)\). Random pivoting is what avoids it, so D is backwards.

Check yourself

Explain why "\(O\)" and "worst case" are not synonyms.

\(O\) chooses a type of bound (an upper bound); best/average/worst chooses which inputs you are measuring. They vary independently — "the best case is \(O(1)\)" and "the worst case is \(\Omega(n^2)\)" are both perfectly ordinary statements.

An algorithm is \(O(n^2)\) and \(\Omega(n)\). Can we say it is \(\Theta\) of anything?

Not from this information. \(\Theta\) requires the same function to be both an upper and a lower bound. Here the two bounds differ, so either the analysis is not tight, or best and worst genuinely differ in class (as in early-exit bubble sort).

Why is average-case analysis less common in this course?

It requires an explicit probability distribution over inputs, which is usually unknown and rarely uniform in practice. Worst case needs no such assumption and yields a guarantee, so it is the default — but you should still say which you are using.

Give an algorithm whose best and worst cases are the same class, and one where they differ.

Same: merge sort — \(\Theta(n\log n)\) on every input, since it always splits fully and merges fully. Also "find the maximum", \(\Theta(n)\) always. Differ: early-exit bubble sort (\(\Theta(n)\) vs \(\Theta(n^2)\)), or linear search (\(\Theta(1)\) vs \(\Theta(n)\)).
