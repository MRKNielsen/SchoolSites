Greedy Algorithms and Hill Climbing

Unit 4 AOS2 · Topic 10 of 17 — trading the guarantee for speed, knowingly

VCE Algorithmics (HESS) · Northcote High School

What a heuristic actually is

Heuristic

A method that finds a good solution quickly, with no guarantee that it is optimal.

  • The word covers both a rule of thumb for choosing (greedy) and a strategy for searching (hill climbing, annealing).
  • What is surrendered is the guarantee — not correctness. A heuristic returns a valid solution; it just may not be the best one.
  • What is gained is polynomial running time on problems where exactness costs exponential time.
Say what you gave up

Any answer describing a heuristic should name the trade explicitly: fast and feasible, but optimality is not guaranteed. That clause is usually a mark.

When a heuristic is the right call

  1. 1 The problem is intractable — the search space grows exponentially, so exhaustive search is out for realistic \(n\).
  2. 2 The solution space is huge but solutions are easy to evaluate — you can score a candidate cheaply even though you cannot enumerate them all.
  3. 3 A good answer is worth having — a 5% worse delivery route today beats a perfect one next century.
  4. 4 Neighbouring solutions are similar in quality — small changes give small score changes, so local search can make progress.
The counter-case

If the problem is in P, a heuristic is the wrong tool — you would be giving up the guarantee for nothing. Never propose a heuristic for shortest path.

Greedy — commit to the best local choice

The method

At each step, make the choice that looks best right now, and never reconsider it.

Greedy TSP — nearest neighbour

Start at any city. Repeatedly travel to the nearest unvisited city. When all cities are visited, return to the start.

  • Fast: \(O(n^2)\) — at each of \(n\) steps, scan the remaining cities.
  • No backtracking, no reconsideration. One pass, one answer.
  • Typically lands within 25% of optimal on realistic instances, and can be much worse on adversarial ones.

Why greedy fails — and when it doesn't

Fails

TSP: taking the nearest city early can strand a distant one, forcing an expensive final leg. Change-making with {1,4,6}: greedy gives 6+1+1, optimum is 4+4.

Provably optimal

Prim's and Kruskal's for minimum spanning tree; Dijkstra for shortest path with non-negative weights. These are greedy — and they are exact.

The distinction that matters

Greedy is a technique, not automatically a heuristic. On problems with the right mathematical structure it provably yields the optimum; elsewhere it is a heuristic. Calling Dijkstra "a heuristic" is wrong.

How to talk about it

"Greedy is optimal for MST because a locally cheapest safe edge is always part of some optimal tree; for TSP no such property holds, so greedy is only a heuristic there."

Hill climbing — improve, repeat

The method

Start from a candidate solution. Generate a neighbour by making a small change. If the neighbour is better, move to it. Repeat until no neighbour improves.

  • Three things must be defined before you can run it: the representation of a solution, the neighbourhood (what counts as a small change), and the objective function (how to score).
  • For TSP: representation = an ordering of cities; neighbourhood = reverse a segment (2-opt); objective = total tour length.
  • Unlike greedy, hill climbing starts with a complete solution and improves it, rather than building one piece by piece.
Exam phrasing

If asked to "describe how to generate a new candidate solution", you are being asked for the neighbourhood. Name a concrete small change: swap two cities in the tour.

The local optimum problem

  • Hill climbing only accepts improvements, so it stops at the first peak it reaches.
  • That peak may be a local optimum — better than everything nearby, worse than the best overall.
  • The algorithm cannot tell the difference. From inside a local optimum, every neighbour looks worse, which is exactly what a global optimum looks like too.
Two partial fixes

Random restarts — run many times from different starts and keep the best. Larger neighbourhoods — more moves to escape by. Neither is a guarantee.

Exam focus

Which description is hill climbing?

Adapted from VCAA Algorithmics (HESS) Written Examination 2023, Section A Q11

A robot navigating back to its charging dock — which is hill climbing on a heuristic function?

Aretraces the exact path it took on the way out
Bcomputes an optimal path back using its map of everywhere it has been
Cpicks a random adjacent open position, and moves there only if it is closer to the dock; repeats
Dpicks a random adjacent position; always moves if closer, and sometimes moves if further, with that probability decreasing over time
Before you look

Option D is also a real algorithm from this course. Which one — and what single word in it rules it out here?

Working it through

  1. 1 A is not a search at all — retracing a known path uses stored information, no objective function, no candidate solutions.
  2. 2 B is an exact method. "Computes an optimal path" means a shortest-path algorithm, not a heuristic — it guarantees the best answer.
  3. 3 C matches hill climbing exactly: generate a neighbour (an adjacent position), evaluate the objective (distance to dock), and move only if it improves. That last clause is the definition.
  4. 4 D adds accepting worse moves with a decreasing probability — that is simulated annealing, Topic 11. The giveaway word is "sometimes".
  5. ✓ Answer: C.
The one-word discriminator

Hill climbing accepts only improvements. Simulated annealing sometimes accepts worsening moves. Every question distinguishing the two turns on that word.

Describe a greedy approach to TSP

Adapted from VCAA Algorithmics (HESS) Written Examination 2021, Section B Q8b

Question (2 marks)

Describe a greedy approach to solving the travelling salesman problem.

Response

Begin at any city and mark it visited. Repeatedly move to the nearest unvisited city from the current one, marking each as visited, until all cities have been visited; then return to the starting city. The choice at each step is locally optimal — the closest available city — and is never reconsidered, which is what makes the approach greedy.

Two marks, two components

One for the procedure, one for identifying what makes it greedy — the locally-best, never-revisited choice. Describing the procedure alone typically earns one.

Elaboration — greedy as a starting point

The 2021 question continues by using the greedy tour as the initial candidate for simulated annealing. That pairing is deliberate and worth understanding.

Random startGreedy start
Initial tour qualityvery pooralready decent
Search time neededlongmuch shorter
Riskwanders for agesmay begin inside a deep local optimum
  • A greedy construction gives local search a decent place to begin, so the improvement phase is not wasted climbing out of a terrible tour.
  • The risk is real though: a strong start can sit in a basin that small moves cannot escape — which is precisely the problem Topic 11 solves.
The standard pipeline

Construct greedily, then improve locally. Two heuristics doing different jobs — one builds, one refines.

Check yourself

Define the three things you must specify before running hill climbing.

Representation — how a candidate solution is encoded (e.g. an ordering of cities). Neighbourhood — what counts as a small change (e.g. reverse a segment). Objective function — how a candidate is scored (e.g. total tour length).

Is Dijkstra's algorithm a heuristic? Justify.

No. It uses a greedy technique — always finalise the closest unvisited node — but for graphs with non-negative weights that choice is provably safe, so it returns the true shortest path every time. A heuristic is defined by giving up the guarantee, and Dijkstra gives up nothing.

Why can hill climbing not detect that it is stuck in a local optimum?

Its only information is the objective values of neighbouring solutions. At a local optimum every neighbour scores worse — which is exactly what a global optimum also looks like from the inside. Distinguishing them would require evaluating solutions outside the neighbourhood.

State one advantage and one limitation of a heuristic for TSP.

Advantage: runs in polynomial time (nearest neighbour is \(O(n^2)\)), so it handles instance sizes where exhaustive search is impossible. Limitation: no guarantee of optimality, and no way to know how far from optimal the answer is without solving the problem exactly.

One sentence to remember

Greedy commits to the best local choice and never looks back; hill climbing keeps improving until nothing nearby is better — and neither can tell a local optimum from a global one.
