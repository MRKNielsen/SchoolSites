The habit to build

Every complexity claim you make this year needs three parts: what you counted, what \(n\) means, and which input you assumed. A bare "\(O(n^2)\)" earns nothing without them.

Why we don't measure in seconds

Suppose you time an algorithm and get 0.8 seconds. What have you learned?

  • That it took 0.8 s on that machine, with that CPU, that language, that compiler, under that background load, for that one input.
  • Change any of those and the number changes. None of that is a property of the algorithm.
  • Worse, it tells you nothing about the input you actually care about — the one ten times larger.
What we want instead

A statement about the algorithm that survives changes of machine, language and input size — something of the form "if the input doubles, the work multiplies by roughly …"

Not useless, though

Timing is still how you verify an analysis. Predict the shape mathematically, then check the measurements match. That is exactly what your workbook does.

What we count instead: elementary operations

An elementary operation is one whose cost does not depend on \(n\): an arithmetic operation, a comparison, an assignment, an array index, a return.

The model

Assume every elementary operation costs the same fixed amount of time. Then the running time is proportional to the number of elementary operations — a property of the algorithm alone.

Where students lose marks

Assuming an operation is elementary when it isn't. list.append(x) is; x in list is not — it scans. Topic 3 is largely about spotting this, and it is the single most common trap in the exam.

Worked example — count, don't guess

Algorithm

sum ← 0
For i ← 1 to n Do
  sum ← sum + i
Return sum

  1. 1 Before the loop: one assignment. Cost 1.
  2. 2 Loop control: the counter is initialised once, then compared and incremented each pass — about \(2n + 1\) operations.
  3. 3 Loop body: one addition and one assignment, \(n\) times — \(2n\).
  4. 4 After: one return. Cost 1.
  5. 5 Total: \(T(n) = 4n + 3\).
Now the important bit

Nobody cares about the 4 or the 3. Change language and they change. What survives is that \(T\) is linear in \(n\).

Why we drop constants and lower-order terms

Take \(T(n) = 4n + 3\) and \(U(n) = 100n\). Which is "faster"?

The principle

Constant factors are engineering. Growth class is mathematics. Big-O deliberately throws away the first so it can talk about the second.

Big-O: the formal definition

Definition

\(f(n) = O(g(n))\) if there exist constants \(c > 0\) and \(n_0 \ge 0\) such that \[ f(n) \le c \cdot g(n) \quad \text{for all } n \ge n_0. \]

  • Read it as: beyond some point, \(f\) is no bigger than a fixed multiple of \(g\).
  • \(c\) absorbs the constant factors you refuse to care about.
  • \(n_0\) lets small inputs misbehave. Nothing is claimed about them.
  • It is an upper bound, and it need not be tight — \(n\) really is \(O(n^5)\), just uselessly so.
Notation warning

The "=" is traditional but misleading; \(O(g)\) is a set of functions. Some texts write \(f \in O(g)\). Either is accepted — but never write \(O(g) = f\).

What \(c\) and \(n_0\) actually do

  • The dashed curve is \(c \cdot g(n)\) — the bound, scaled up by \(c\).
  • Left of \(n_0\) the solid curve \(f\) pokes above it. Allowed.
  • Right of \(n_0\) it never does again. That is the whole claim.
  • You get to choose \(c\) and \(n_0\). To prove a bound, exhibit one working pair — you need not find the best one.
Say it in words

"Eventually, and up to a constant factor, \(f\) grows no faster than \(g\)." The two escape clauses — eventually and up to a constant — are exactly \(n_0\) and \(c\).

Worked example — proving \(3n^2 + 5n + 2 = O(n^2)\)

Exam questions rarely ask for this proof, but doing it once makes the definition stop feeling arbitrary.

  1. 1 Goal. Find \(c\) and \(n_0\) with \(3n^2 + 5n + 2 \le c\,n^2\) for all \(n \ge n_0\).
  2. 2 Bound each term by a multiple of \(n^2\). For \(n \ge 1\): \(5n \le 5n^2\) and \(2 \le 2n^2\).
  3. 3 Add them. \(3n^2 + 5n + 2 \le 3n^2 + 5n^2 + 2n^2 = 10n^2\).
  4. 4 Read off the witnesses. Take \(c = 10\), \(n_0 = 1\). Done.
  5. ✓ Any larger \(c\) also works. There is nothing special about 10 — which is the point.
The trick worth keeping

To bound a sum, bound every term by the largest term's growth class, then count the terms. It works every time for polynomials.

Ask instead

"Slow for what \(n\)?" A quadratic algorithm on \(n = 50\) is instant. On \(n = 10^6\) it is a fortnight.

Big-O arithmetic — the three working rules

Rule 1 · Constants vanish

\(O(c \cdot f) = O(f)\) for any constant \(c > 0\).  So \(O(500n) = O(n)\).

Rule 2 · Sums keep the winner

\(O(f + g) = O(\max(f, g))\).  Sequential blocks of code: the slowest block wins. \(O(n^2 + n) = O(n^2)\).

Rule 3 · Nesting multiplies

A loop running \(f(n)\) times whose body costs \(g(n)\) costs \(O(f \cdot g)\).  This is the rule people forget when the "body" is a function call.

Rule 2 has a condition

It works because the terms are added a constant number of times. Adding \(n\) terms each \(O(n)\) gives \(O(n^2)\), not \(O(n)\).

Worked example — applying all three rules

Simplify

\(T(n) = 7n^3 + 200n^2\log n + 5000n + 42\)

  1. 1 Rule 1 on each term: the coefficients 7, 200, 5000, 42 all go. Left with \(n^3\), \(n^2\log n\), \(n\), \(1\).
  2. 2 Rank them. Is \(n^3\) or \(n^2\log n\) bigger? Divide both by \(n^2\): compare \(n\) against \(\log n\). \(n\) wins for large \(n\).
  3. 3 Rule 2: the maximum is \(n^3\).
  4. ✓ \(T(n) = O(n^3)\).
Transferable move

To compare two terms, divide both by their common factor and compare what's left. It turns an intimidating comparison into an obvious one.

The dominance ordering

Every function below is dominated by everything to its right, for large enough \(n\):

\(1 \prec \log n \prec \sqrt{n} \prec n \prec n\log n \prec n^2 \prec n^3 \prec 2^n \prec n!\)

  • Any polynomial beats any logarithm. Any exponential beats any polynomial — including \(n^{100}\).
  • Log bases don't matter: \(\log_2 n\) and \(\log_{10} n\) differ by a constant factor, so Rule 1 erases the base.
  • Comparing \(n^a\) and \(n^b\)? Bigger exponent wins. Comparing \(a^n\) and \(b^n\)? Bigger base wins, and the gap is enormous.
Quick check

Rank these: \(n^{1.5}\), \(n\log n\), \(100n\), \(2^{\sqrt{n}}\).  (Answer: \(100n \prec n\log n \prec n^{1.5} \prec 2^{\sqrt n}\) — the last is exponential in disguise.)

Read the mark allocation

When a question is worth 3 marks and asks you to analyse or justify, the bound itself is rarely more than one of them. The other marks are for the reasoning that produced it — so write the reasoning.

Exam focus

Which family has the largest Big-O complexity?

Adapted from VCAA Algorithmics (HESS) Written Examination 2023, Section A Q12

Choose one — which grows fastest as \(n \to \infty\)?

A\(O(50n^2 + 400000n)\)
B\(O(3n^{8})\)
C\(O(9000 \log_2 n)\)
D\(O(4000 \times (0.5)^{\,n})\)
Before you look

Two of these are designed to catch you. Which two, and what is the catch in each?

Working it through

  1. 1 Strip the constants (Rule 1). A → \(n^2 + n\); B → \(n^8\); C → \(\log n\); D → \((0.5)^n\).
  2. 2 Simplify A (Rule 2): \(\max(n^2, n) = n^2\). The 400000 is a decoy — it is huge, but constant.
  3. 3 Look hard at D. Base \(0.5 < 1\), so \((0.5)^n\) shrinks toward 0. It is bounded above, hence \(O(1)\) — the smallest option, not the largest.
  4. 4 Rank the survivors: \(\log n \prec n^2 \prec n^8\).
  5. ✓ Answer: B.
The two traps

A punishes anyone who compares the big constant 400000 instead of the growth. D punishes anyone who sees an exponent and assumes "exponential = biggest" without checking the base.

Elaboration — why a shrinking function is \(O(1)\)

Option D is worth dwelling on, because the reasoning generalises.

  • \((0.5)^n\) takes values \(0.5, 0.25, 0.125, \ldots\) — always positive, never above \(0.5\).
  • Apply the definition with \(g(n) = 1\): is \((0.5)^n \le c \cdot 1\) for all \(n \ge n_0\)? Yes — take \(c = 1\), \(n_0 = 1\).
  • So \(4000 \times (0.5)^n = O(1)\). A bounded function is always \(O(1)\), whatever shape it has.
The general lesson

\(a^n\) explodes when \(a > 1\) and collapses when \(a < 1\). The exponent is not what makes a function exponential — the base is.

Push it further

Is \(n \times (0.5)^n\) also \(O(1)\)? (Yes — the exponential decay beats the linear growth. Worth convincing yourself with a few values.)

Check yourself

State the formal definition of \(f(n) = O(g(n))\), and explain the role of each constant.

There exist \(c > 0\) and \(n_0 \ge 0\) with \(f(n) \le c\,g(n)\) for all \(n \ge n_0\). \(c\) absorbs constant factors, so the claim is machine-independent; \(n_0\) restricts the claim to large inputs, so small-\(n\) behaviour cannot break it.

Simplify \(T(n) = 6n^2 + 12n\log n + 900\) and justify each step.

\(O(n^2)\). Rule 1 drops 6, 12, 900. Rule 2 keeps the maximum of \(n^2\), \(n\log n\), \(1\); dividing the first two by \(n\) compares \(n\) with \(\log n\), and \(n\) dominates. So \(n^2\) wins.

An algorithm is \(O(n^3)\) and handles \(n = 500\) in 1 second. Estimate \(n = 5000\).

\(n\) grows ×10, so the work grows by about \(10^3 = 1000\) → roughly 1000 seconds ≈ 17 minutes. Note the word about: Big-O supports an order-of-magnitude estimate, not a precise one.

True or false: an \(O(n^2)\) algorithm is always slower than an \(O(n\log n)\) one.

False. Big-O describes behaviour for large \(n\) only. With a small constant factor, the quadratic can win for small inputs — the crossover point is exactly what \(n_0\) acknowledges. It is also an upper bound, so an \(O(n^2)\) algorithm might in fact be \(O(n)\).

One sentence to remember

Big-O names the growth class, deliberately discarding constants — so it answers "what happens when the input gets big?" and refuses to answer "how many seconds?"
