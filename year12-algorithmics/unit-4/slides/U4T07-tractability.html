Tractability, P and NP

Unit 4 AOS2 · Topic 7 of 17 — when better analysis stops helping

VCE Algorithmics (HESS) · Northcote High School

A different kind of question

AOS1 asked how fast is this algorithm? AOS2 asks how hard is this problem?

  • An algorithm has a complexity. You can improve it by writing a better algorithm.
  • A problem has a difficulty. No amount of cleverness moves it — the difficulty is a property of the task itself.
  • This topic is about classifying problems, not algorithms.
Why it matters practically

If a problem is intractable, "just optimise the code" is not a plan. You must change the goal — accept an approximate answer, restrict the inputs, or solve a different problem. That is the whole of AOS2.

Tractable and intractable

Tractable

A problem is tractable if there exists an algorithm that solves it in polynomial time — \(O(n^k)\) for some constant \(k\).

Intractable

A problem is intractable if no polynomial-time algorithm for it exists.

  • The line is drawn at polynomial versus super-polynomial, not at "fast" versus "slow". \(O(n^{100})\) is technically tractable and hopeless in practice.
  • The reason the line sits there: polynomials are closed under composition and addition, so "polynomial" survives being built into larger algorithms. Exponentials do not.
Note the quantifier

"No polynomial algorithm exists" — not "we haven't found one". That is a claim about all possible algorithms, which is why proving intractability is hard.

The argument that settles it

Buy a machine 1000× faster. A cubic algorithm now handles 10× the input. An algorithm costing \(2^n\) handles about 10 more items. Hardware scales polynomial algorithms; it does not scale exponential ones.

At \(n = 100\), \(2^n\) exceeds the estimated number of atoms in the observable universe. This is not an engineering problem.

First, restrict to decision problems

Decision problem

A problem whose answer is yes or no.

Optimisation versionDecision version
Find the shortest tourIs there a tour of length \(\le k\)?
Maximise value packed in the knapsackCan value \(\ge k\) be packed?
Find the fewest colours to colour the graphCan the graph be coloured with \(k\) colours?
Why bother

The classes P and NP are defined for decision problems. The two versions are closely tied: if you could answer the decision version quickly for every \(k\), you could find the optimum by asking repeatedly. So hardness transfers.

The class P

P

The set of decision problems that can be solved by an algorithm running in polynomial time.

  • "Is there a path from \(u\) to \(v\)?" — run BFS. In P.
  • "Is this number even?" — check the last digit. In P.
  • "Does this graph have a spanning tree of weight \(\le k\)?" — run Prim's and compare. In P.
P is the formal version of "tractable"

When we say a problem is tractable, we mean it is in P. The two words are used almost interchangeably in this course.

The class NP — the one everyone misstates

NP

The set of decision problems for which a proposed solution can be checked in polynomial time.

NP does not stand for "non-polynomial"

It stands for nondeterministic polynomial. Writing "NP means it can't be done in polynomial time" is wrong and is penalised — not least because every problem in P is also in NP.

  • Solving vs checking. Finding a tour shorter than 500 km might take forever; handed one, you add up the edges and compare. That check is polynomial, so the problem is in NP.
  • Think of it as: if a friend hands you the answer, can you verify it quickly?

How the classes sit

Drawn assuming P ≠ NP — which nobody has proved.

  • P \(\subseteq\) NP. If you can solve it quickly, you can check it quickly — solve it yourself and compare.
  • NP-complete problems sit inside NP and are the hardest members of it.
  • NP-hard problems are at least as hard as the NP-complete ones, but need not be in NP at all.
The open question

Is P = NP? If yes, the middle ellipse swallows everything and checking-quickly implies solving-quickly. Almost nobody expects that, but nobody has proved otherwise.

Exam focus

Which statement is incorrect?

Adapted from VCAA Algorithmics (HESS) Written Examination 2022, Section A Q19

One of these four is false — which?

ANP-complete problems are the hardest problems in NP
BEvery problem in P is also in NP
CA proposed solution to a problem in NP can be checked in polynomial time
DEvery problem in NP is NP-complete
Think first

Three of these are definitions restated. One reverses a containment. Which direction is being flipped?

Working it through

  1. 1 A is true — that is what NP-complete means: in NP, and at least as hard as everything else in NP.
  2. 2 B is true — if you can solve it in polynomial time you can verify a claimed answer in polynomial time by solving it yourself.
  3. 3 C is true — that is the definition of NP.
  4. 4 D is false. NP-complete is a subset of NP, not all of it. Counterexample: "is there a path from \(u\) to \(v\)?" is in P, hence in NP, and is certainly not NP-complete.
  5. ✓ Answer: D.
The technique

For "which is incorrect" questions about classes, test each claim by finding a counterexample. One concrete problem that satisfies the claim's premise but not its conclusion settles it.

Correct the student's definition

Adapted from VCAA Algorithmics (HESS) Written Examination 2021, Section B Q11b

Question (3 marks)

A student defines intractable problems as follows:

"They are problems for which there is no way of checking a solution quickly, and so it is impossible to know whether they are decidable or not."

Explain why this definition is incorrect, and provide an improved definition of intractable problems.

Response

Two errors. First, it confuses solving with checking — many intractable problems (the NP-complete ones) have solutions that can be checked quickly; what is missing is a fast way to find one. Second, intractability and decidability are separate ideas: an intractable problem is still decidable — an algorithm exists, it is simply too slow to be useful.

Improved definition: a problem is intractable if no algorithm exists that solves it in polynomial time in the size of its input.

Elaboration — two axes, not one

The student's error is worth dwelling on, because it is the single most common confusion in AOS2–3.

DecidableUndecidable
Tractableshortest path, sorting— (impossible)
IntractableTSP, graph colouringthe Halting Problem
  • Decidability asks: does an algorithm exist at all?
  • Tractability asks: does a fast one exist?
  • You only get to ask the second question once the answer to the first is yes.
Say it precisely

"TSP is impossible to solve" is wrong — brute force solves it perfectly. It is intractable: solvable in principle, not in practice. Topic 13 handles genuine impossibility.

Check yourself

Define P and NP, and state the relationship between them.

P: decision problems solvable in polynomial time. NP: decision problems whose proposed solutions are verifiable in polynomial time. \(P \subseteq NP\), because solving a problem yourself is one way of verifying an answer. Whether the containment is strict is the open P vs NP question.

Why is the tractable/intractable line drawn at polynomial time?

Polynomials are closed under addition and composition, so combining polynomial-time components keeps the whole polynomial — the class is robust. And faster hardware multiplies the feasible input size for a polynomial algorithm, while adding only a constant to it for an exponential one.

Give the decision version of "find the minimum number of colours to colour this graph".

"Given a graph \(G\) and an integer \(k\), can \(G\) be properly coloured using at most \(k\) colours?" The answer is yes/no, and a proposed colouring can be verified in polynomial time by checking every edge — so the problem is in NP.

A student writes "NP means non-polynomial". Correct them.

NP stands for nondeterministic polynomial, and describes problems whose solutions can be checked in polynomial time. Since every problem in P is also in NP, "non-polynomial" would be self-contradictory — sorting is in NP and is certainly polynomial.

One sentence to remember

Tractable means a polynomial algorithm exists; NP means a proposed answer can be checked quickly — and checking quickly is not the same as solving quickly.
