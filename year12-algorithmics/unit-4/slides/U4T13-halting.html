The Halting Problem and Undecidability

Unit 4 AOS3 · Topic 13 of 17 — a problem provably no algorithm can solve

VCE Algorithmics (HESS) · Northcote High School

Decidable and undecidable

Decidable

A decision problem is decidable if there exists an algorithm that, for every instance, halts and returns the correct yes/no answer.

Undecidable

A decision problem is undecidable if no such algorithm exists.

  • Note the two requirements on the algorithm: it must always halt, and it must be always correct. Failing either disqualifies it.
  • Undecidable is not "hard". It is not "we haven't found the algorithm yet". It is a proof that none can exist.
The word that carries the meaning

Every. Undecidability is about the absence of a single algorithm that works for all instances — not about individual instances being unsolvable.

The error almost everyone makes

Wrong

"An undecidable problem is one where no instance can be solved."

Right

"An undecidable problem is one for which no single algorithm correctly decides every instance."

  • Plenty of individual halting questions are easy. While True Do nothing obviously never halts; Return 1 obviously does.
  • Many instances are decidable by inspection, by analysis, or by simply running the program and watching it stop.
  • What cannot exist is a uniform procedure that settles all of them.
Say it this way

"There exist algorithms that solve many instances of an undecidable problem — what is impossible is one algorithm that solves them all."

Stating the Halting Problem

The Halting Problem

Input: a description of a program \(P\), and an input \(x\).
Question: does \(P\) halt when run on \(x\)?
Turing's result (1936): no algorithm decides this for all \((P, x)\).

  • It is a decision problem — the answer is yes or no.
  • The input is a program, which is just data. That self-reference is what makes the proof possible.
  • "Just run it and see" fails: if it hasn't stopped after an hour, you cannot tell whether it never will, or needs another minute.
Why not just wait longer

Waiting can confirm halting, but never confirm non-halting. A decision procedure must halt with an answer in both cases.

The proof, in five moves

  1. 1 Assume such an algorithm exists. Call it \(H(P, x)\): it always halts, returning "halts" or "loops".
  2. 2 Construct a new program \(D\) taking one input \(P\): run \(H(P, P)\); if it says "halts", enter an infinite loop; if it says "loops", halt immediately.
  3. 3 Ask the fatal question: what does \(D\) do when run on itself — \(D(D)\)?
  4. 4 Case analysis. If \(D(D)\) halts, then \(H\) said "halts", so by construction \(D\) loops — contradiction. If \(D(D)\) loops, then \(H\) said "loops", so \(D\) halts — contradiction.
  5. ✓ Conclusion: both cases are impossible, so the assumption fails. No such \(H\) exists.
The structure has a name

Proof by contradiction, using self-reference — feeding the program its own description. Diagonalisation, the same device Gödel used.

Why \(D\) is a legitimate program

The step students query is move 2 — surely \(D\) is a cheat?

  • \(D\) is built entirely from things we assumed available: a call to \(H\), an if, an infinite loop, and a halt. Nothing exotic.
  • Feeding a program its own description is unremarkable — a compiler compiles itself; a text editor edits its own source. Programs are data.
  • So if \(H\) existed, \(D\) would too. Since \(D\) cannot exist, neither can \(H\).
The everyday version

"This sentence is false." Not a linguistic trick — the same self-referential structure, which is why no consistent truth-value can be assigned.

Common misstatement

The proof does not show that \(D\) is a badly-behaved program. It shows that the assumption that \(H\) exists is what produces the contradiction. \(H\) is the culprit.

What follows

  • The Entscheidungsproblem is answered — negatively. No mechanical procedure decides the provability of every mathematical statement.
  • Perfect program verification is impossible. No tool can decide, for every program, whether it terminates, or whether it contains an infinite loop.
  • Many related problems inherit undecidability by reduction: does this program ever output 5? Are these two programs equivalent? Does this code ever reach line 12?
  • But useful tools still exist. Static analysers, type checkers and linters work on large classes of realistic programs — they simply cannot be complete and always-correct on all of them.
The honest summary

Undecidability rules out a universal, always-correct tool. It does not rule out tools that are correct when they answer and sometimes say "don't know".

Exam focus

Which statement is incorrect?

Adapted from VCAA Algorithmics (HESS) Written Examination 2023, Section A Q17

One of these about undecidable problems is false — which?

Aundecidable problems are decision problems
Bno instance of an undecidable problem can ever be solved
Cthere exist algorithms that solve many instances of an undecidable problem
Dthere is no algorithm that correctly solves every instance of an undecidable problem
Before you look

Options B and C directly contradict each other, so exactly one is false. Which one matches the definition?

Working it through

  1. 1 A is true — decidability is defined for yes/no problems, so undecidable problems are by definition decision problems.
  2. 2 D is true — that is precisely the definition of undecidable.
  3. 3 C is true — many individual instances are easy. While True Do nothing plainly never halts, and we can say so.
  4. 4 B is false, and is the misconception this whole topic exists to remove. Individual instances are frequently solvable; what fails is a uniform algorithm.
  5. ✓ Answer: B.
C and D together are the definition

They are not in tension. Many instances are solvable (C); not all by one algorithm (D). Holding both at once is the understanding being tested.

Correct the student's explanation

Adapted from VCAA Algorithmics (HESS) Written Examination 2021, Section B Q11a

Question (3 marks)

A student explains: "An undecidable problem is one where there is no instance of the problem that can be solved."

Discuss why this explanation is incorrect, and provide an improved explanation of what an undecidable problem is.

Response

Why it is incorrect: it misplaces the quantifier. Undecidability is a claim about the non-existence of a general algorithm, not about the unsolvability of individual instances. Many instances of an undecidable problem can be solved — for the Halting Problem, we can readily see that While True Do nothing does not halt, and that a program with no loops does.

Improved explanation: a problem is undecidable if there is no algorithm that, for every possible instance, halts and returns the correct answer. Individual instances may well be decidable by inspection or by special-case reasoning; what cannot exist is a single procedure that settles them all.

Elaboration — the quantifier is the whole idea

Both exam questions on this topic test the same thing: where the word "every" sits.

StatementMeaningTrue?
There is no algorithm that solves every instancethe definition of undecidableyes
For every instance there is no algorithm that solves itevery instance individually unsolvableno
  • The two sentences use identical words. Swapping the order of "there is no algorithm" and "every instance" reverses the meaning completely.
  • The first says one thing about the collection. The second says something about each member.
A phrase that keeps you safe

Begin every answer with "there is no single algorithm that…". The word single forces the quantifier into the right place.

Check yourself

State the Halting Problem precisely: input, question, result.

Input: a description of a program \(P\) and an input \(x\). Question: does \(P\) halt when run on \(x\)? Result: Turing proved (1936) that no algorithm decides this correctly for all pairs \((P, x)\) — the problem is undecidable.

Outline the proof in five moves.

(1) Assume a decider \(H(P,x)\) exists. (2) Construct \(D(P)\): run \(H(P,P)\), loop if it says "halts", halt if it says "loops". (3) Ask what \(D(D)\) does. (4) Both cases contradict: halting implies looping and vice versa. (5) Conclude \(H\) cannot exist.

Is an undecidable problem also intractable? Is an intractable problem undecidable?

Undecidable problems have no algorithm at all, so the question of speed does not arise — they sit outside the tractable/intractable distinction, which applies to decidable problems. Intractable problems are decidable: an algorithm exists, it is merely too slow. So neither implies the other.

Why can't a debugger warn you about every infinite loop?

Doing so would decide the Halting Problem, which is impossible. Real tools detect common loop patterns and report those, staying silent or saying "unknown" elsewhere — correct when they answer, but necessarily incomplete.
