Two escapes that keep the exact answer

Topic 7 said hard problems need a change of plan. There are two kinds of plan.

  • Exact techniques — still guarantee the optimal answer, but avoid re-doing work or exploring hopeless branches. This topic.
  • Heuristics — give up the guarantee in exchange for speed. Topics 10–11.
Be precise about what is gained

Dynamic programming and backtracking often turn "impossible" into "feasible for realistic \(n\)". They do not make NP-complete problems tractable in the formal sense — the worst case is still exponential.

Dynamic programming — never solve the same subproblem twice

The technique

Break the problem into overlapping subproblems, solve each once, store the result, and build larger answers from stored smaller ones.

  • Top-down (memoisation): write the natural recursion, but check a cache before recomputing.
  • Bottom-up (tabulation): fill a table from the smallest subproblem upward, so every value you need is already there.
  • Same results, same complexity. Bottom-up avoids deep recursion; top-down only computes what it actually needs.
You have already seen this

Topic 5's memoised Fibonacci is dynamic programming: \(\Theta(\phi^n)\) collapses to \(\Theta(n)\) because each of the \(n\) subproblems is solved once.

When dynamic programming applies

Two required properties

Optimal substructure — an optimal solution is built from optimal solutions to subproblems.
Overlapping subproblems — the same subproblems recur many times.

  • Miss overlapping and there is nothing to cache — merge sort's subproblems are all distinct, so DP buys nothing.
  • Miss optimal substructure and the technique is invalid, not merely useless: combining optimal parts would not give an optimal whole.
A counterexample worth knowing

Longest simple path in a graph has no optimal substructure — gluing two longest paths can revisit a node, breaking simplicity. DP does not apply.

Worked example — making change

Problem

Denominations {1, 4, 6}. Make 8 using the fewest coins.

  1. 1 Subproblem: \(C(v)\) = fewest coins to make value \(v\). Base: \(C(0) = 0\).
  2. 2 Recurrence: \(C(v) = 1 + \min\{\,C(v - d)\;:\; d \in \{1,4,6\},\, d \le v\,\}\).
  3. 3 Fill upward: \(C(1){=}1,\; C(2){=}2,\; C(3){=}3,\; C(4){=}1,\; C(5){=}2,\; C(6){=}1,\; C(7){=}2\).
  4. 4 Then \(C(8)\): \(1 + \min(C(7), C(4), C(2)) = 1 + \min(2, 1, 2) = 2\).
  5. ✓ Two coins: 4 + 4.
Why greedy fails here

Greedy takes the largest coin first: 6, then 1, then 1 — three coins. The denominations {1,4,6} are chosen precisely so greed is wrong. Topic 10 explores when greed is safe.

Backtracking — abandon a branch early

The technique

Build a candidate solution one decision at a time. Whenever a partial candidate cannot possibly be completed into a valid or better solution, abandon it immediately and step back.

  • The search space is a tree of partial decisions. Backtracking prunes whole subtrees without visiting them.
  • It remains an exhaustive search — every solution not pruned is still explored, so the answer is exact.
  • Worst case is unchanged: if nothing can be pruned, you visit everything.
The everyday version

Sudoku. Enter a digit; if a row or column is now impossible, rub it out and try the next — rather than filling all 81 squares and only then checking.

Worked example — placing queens

  1. 1 Decisions: one queen per column, choosing its row.
  2. 2 Brute force: \(8^8 \approx 16.7\) million placements to check.
  3. 3 The pruning test: after placing each queen, check it against those already placed. If it is attacked, abandon every arrangement extending this prefix.
  4. 4 Effect: rejecting a bad queen in column 2 removes \(8^6\) arrangements — over a quarter of a million — at the cost of one test.
  5. ✓ Same exact answer, a tiny fraction of the work.

Exam focus

Why does backtracking miss nothing?

Adapted from VCAA Algorithmics (HESS) Written Examination 2022, Section B Q6b

Question (3 marks)

A student uses a backtracking algorithm that abandons a branch whenever it reaches a partial arrangement that already violates a constraint. She observes that many complete arrangements are never generated at all, because the algorithm backtracks before reaching them.

Explain why the algorithm still finds the optimal solution despite not generating those arrangements.

Frame your answer

The claim to establish is precise: the arrangements skipped were guaranteed not to be optimal. Why guaranteed?

Working it through

  1. 1 What the pruning test establishes. When a partial arrangement violates a constraint, every completion of it inherits that violation — extending a candidate never removes a constraint already broken.
  2. 2 So the skipped arrangements are all invalid. They were not merely unpromising; they could not have been solutions at all.
  3. 3 Therefore nothing optimal is lost. The optimum lies among the valid arrangements, and every valid arrangement still lies on an unpruned branch.
  4. ✓ The search remains exhaustive over the feasible region — it simply declines to enumerate the infeasible part.
The sentence that earns the third mark

"Once a constraint is violated, no extension of that partial solution can satisfy it — so the entire subtree is infeasible and can be discarded without checking."

Elaboration — pruning is not always safe

The argument above worked because the test was about feasibility. Pruning on quality needs more care.

Sound

"This partial tour already exceeds the best complete tour found so far." Edge weights are non-negative, so extending it can only make it longer. Safe to prune.

Unsound

"This partial tour looks longer than average, so abandon it." A bad prefix can still lead to the best complete tour. Pruning here can lose the optimum.

The dividing line

Prune only when you can prove no completion of this prefix beats what we already have. That proof is what separates branch-and-bound (exact) from a heuristic (not).

Connects forward

Deliberately unsound pruning, done well, is exactly what Topics 10–11 are about — trading the guarantee for speed, knowingly.

Check yourself

State the two properties a problem needs for dynamic programming, and what goes wrong if each is missing.

Optimal substructure — without it, combining optimal subsolutions gives a wrong answer, so the method is invalid. Overlapping subproblems — without it, nothing is ever reused, so caching adds memory cost for no speed gain (merge sort is the standard example).

With coins {1, 4, 6}, why does greedy fail to make 8 optimally?

Greedy takes 6 first, leaving 2, which needs two 1s — three coins total. The optimum is 4 + 4, two coins. Greedy commits to a locally best choice that rules out the globally best combination; DP considers all denominations at every value.

Does backtracking improve the worst-case complexity of an exponential problem?

No. If nothing can be pruned, every branch is explored and the cost is the full exponential. Backtracking improves typical performance dramatically but leaves the worst case — and therefore the tractability classification — unchanged.

Distinguish memoisation from tabulation.

Both store subproblem results. Memoisation is top-down: keep the natural recursion, consult a cache before recomputing, and only ever compute subproblems actually needed. Tabulation is bottom-up: fill a table from the smallest case, avoiding recursion depth but sometimes computing entries never used.

One sentence to remember

Dynamic programming removes repeated work and backtracking removes doomed work — both keep the exact answer, and neither changes the worst case.
