Analysing Iterative Pseudocode

Unit 4 AOS1 · Topic 3 of 6 — reading a bound off the page, and the trap that costs the most marks

VCE Algorithmics (HESS) · Northcote High School

The method — four questions, every time

  1. 1 What is \(n\)? Name it. Length of a list? Number of nodes? If there are two sizes, name both.
  2. 2 How many times does each loop run? In terms of \(n\) — not "a few", not "\(i\) times".
  3. 3 What does the body cost? This is the step people skip. Look at every line, especially calls to other algorithms.
  4. 4 Combine. Nesting multiplies, sequence takes the maximum.
Write it down in this order

An answer that names \(n\), states each loop's count, states the body cost, then multiplies, earns every method mark even if the final simplification slips.

Patterns 1 and 2 — single and nested loops

Single loop

For i ← 1 to n Do
  total ← total + L[i]

Runs \(n\) times, body \(O(1)\) → \(\Theta(n)\).

Nested, both to n

For i ← 1 to n Do
  For j ← 1 to n Do
    count ← count + 1

\(n\) outer × \(n\) inner × \(O(1)\) → \(\Theta(n^2)\).

Why multiplication is right

The inner loop runs in full for each outer iteration. \(n\) repetitions of \(n\) units of work is \(n \times n\). Nesting depth \(d\) with each loop to \(n\) gives \(\Theta(n^d)\).

Pattern 3 — the triangular loop

Inner bound depends on the outer counter

For i ← 1 to n Do
  For j ← i to n Do
    count ← count + 1

  1. 1 When \(i = 1\) the inner loop runs \(n\) times; \(i = 2\) gives \(n-1\); … ; \(i = n\) gives 1.
  2. 2 Total \(= n + (n-1) + \cdots + 1 = \dfrac{n(n+1)}{2}\).
  3. 3 Expand: \(\dfrac{n^2 + n}{2}\). Drop the constant and the lower term.
  4. ✓ \(\Theta(n^2)\) — the same class as the full square, despite doing half the work.
Do not write \(\Theta(n^2/2)\)

The \(\tfrac12\) is a constant factor. It is real, and it matters to a benchmark — but it is invisible to Big-O by construction.

Pattern 4 — halving loops are logarithmic

Multiplicative counter

i ← n
While i > 1 Do
  i ← i / 2

  • Values of \(i\): \(n, \tfrac n2, \tfrac n4, \ldots, 1\).
  • How many halvings reach 1? The \(k\) with \(n/2^k = 1\), i.e. \(k = \log_2 n\).
The test

If the counter changes by multiplication or division, the loop is logarithmic. If it changes by addition or subtraction, it is linear.

Doubling counts too

i ← 1; While i < n Do i ← i * 2 is also \(\Theta(\log n)\) — same reasoning, run backwards.

Combine it

A loop to \(n\) containing a halving loop gives \(\Theta(n\log n)\) — the classic linearithmic shape.

The trap: an innocent-looking call

This is the single most expensive mistake in AOS1

A loop body that calls another algorithm is not automatically \(O(1)\). You must analyse the call and multiply it in.

Exam focus

Analyse this implementation

Adapted from VCAA Algorithmics (HESS) Written Examination 2022, Section B Q9a

Question (3 marks)

A programmer stores a graph's node names in a list nodes, and for each node stores a list of its adjacent nodes in a dictionary edges, where edges[u] is the list of nodes adjacent to u.

Algorithm isAdjacent(nodes, edges, u, v):
  Foreach value in edges[u] as neighbour Do
    If neighbour = v Do Return True
  Return False

Algorithm closure(nodes, edges):
  Foreach value in nodes as i Do
    Foreach value in nodes as j Do
      Foreach value in nodes as k Do
        If isAdjacent(nodes,edges,i,k) AND isAdjacent(nodes,edges,j,k) Do
          Append i to edges[j]

Appending is a constant time operation. Let \(n\) be the number of nodes. Analyse the time complexity as a function of \(n\) and hence determine the Big-O complexity.

Working it through

  1. 1 Name \(n\): the number of nodes. Note nodes has length \(n\), and each edges[u] has length up to \(n-1\).
  2. 2 The loops: three nested Foreaches over nodes — that is \(n \times n \times n = n^3\) iterations.
  3. 3 The body — the actual question. It calls isAdjacent twice. Each call walks edges[u], which can hold up to \(n-1\) entries. So the body is \(O(n)\), not \(O(1)\).
  4. 4 Multiply: \(n^3\) iterations \(\times\) \(O(n)\) per iteration.
  5. ✓ \(O(n^4)\). Anyone who assumed the body was constant wrote \(O(n^3)\) and lost the marks.
Why this question is set

Floyd–Warshall is \(\Theta(n^3)\) — when adjacency is checked in \(O(1)\) with a matrix. The question hands you a correct algorithm with a bad data structure and asks whether you noticed.

The follow-up parts

b. (1 mark)

Describe a family of graphs with \(n\) nodes that would produce the worst case asymptotic running time.

Response

Complete graphs (every node adjacent to every other). Then each edges[u] holds \(n-1\) entries, so every isAdjacent call scans the full list and the \(O(n)\) body cost is actually attained. On a sparse graph — say each node with a constant number of neighbours — the body would be \(O(1)\) and the whole thing \(O(n^3)\).

c. (1 mark)

How could the implementation be changed to improve its asymptotic time complexity?

Response

Store adjacency in an adjacency matrix (or a dictionary of sets), so isAdjacent becomes an \(O(1)\) lookup instead of an \(O(n)\) scan. The triple loop is unchanged, so the algorithm drops from \(O(n^4)\) to \(O(n^3)\).

Elaboration — same algorithm, different structure

Part c is the lesson of this whole topic: complexity is a property of the algorithm plus its data structures, not the algorithm alone.

OperationAdjacency listAdjacency matrix
Is \(u\) adjacent to \(v\)?\(O(\deg u)\)\(O(1)\)
Visit all neighbours of \(u\)\(O(\deg u)\)\(O(n)\)
Space\(O(|V| + |E|)\)\(O(|V|^2)\)
There is no free lunch

The matrix wins the adjacency test and loses the neighbour walk and the space. Which structure is "better" depends entirely on which operation your algorithm performs most — which is a C7 comparison argument, and exactly what Memo 02 asks for.

Practise spotting the trap

For i ← 1 to n Do /   If L[i] in Seen Do … /   Append L[i] to Seen — complexity, with Seen a list?

\(O(n^2)\). The loop runs \(n\) times, but in Seen scans a list that grows to length \(n\) — an \(O(n)\) body. Switch Seen to a set or dictionary and the membership test becomes \(O(1)\), giving \(O(n)\) overall.

For i ← 1 to n Do /   Sort(L) — with \(|L| = n\).

\(O(n^2\log n)\). \(n\) iterations, each doing an \(O(n\log n)\) sort. (And note the sort is pointless after the first pass — a complexity analysis often exposes redundant work.)

Two sequential loops, one \(\Theta(n)\) and one \(\Theta(n^2)\). Total?

\(\Theta(n^2)\). Sequence takes the maximum, not the product — the loops run one after the other, so the costs add, and \(n^2 + n = \Theta(n^2)\). Only nesting multiplies.

For i ← 1 to n Do /   j ← n /   While j > 1 Do j ← j / 3

\(\Theta(n\log n)\). The outer loop is linear; the inner divides by 3 each pass, so it runs \(\log_3 n\) times. The base 3 is a constant factor on the logarithm, so it vanishes — \(\log_3 n = \Theta(\log n)\).
