The Travelling Salesman Problem

Unit 4 AOS2 · Additional topic 3 of 4 — the classic intractable problem, from brute force to 2-opt

VCE Algorithmics (HESS) · Northcote High School

The problem

Travelling salesman problem (TSP)

Given a weighted graph, find the lowest-cost cycle that visits every node exactly once and returns to where it started.

  • A cycle through every node exactly once is a Hamiltonian cycle. TSP asks for the cheapest one.
  • Applications: delivery and pick-up routes, drilling holes in circuit boards, ordering jobs on a machine where changeover time depends on the order.
Three things it is not

Not an MST — a tree, not a cycle. Not all-pairs shortest paths — that is Floyd–Warshall. Not every edge once — that is an Euler circuit. VCAA has used all three as distractors.

Decision and optimisation

VersionQuestion askedOutputClass
OptimisationWhat is the cheapest tour?a tourNP-hard
DecisionIs there a tour of total weight less than \(X\)?yes / noNP-complete
  • The decision version is in NP: a proposed tour can be checked quickly, even though finding one seems to need a search.
  • The optimisation version is not known to be in NP — given a tour, you cannot quickly confirm that no cheaper one exists.
  • They stand or fall together: a fast algorithm for either would give a fast algorithm for the other (binary search on \(X\)).
Say which one you mean

"TSP is NP-complete" is only true of the decision version. In an extended response, name the version before you classify it.

Think

How many different tours are there starting from A? How would you be sure you had the shortest?

Answer

Fix A as the start. The other 5 towns can be ordered in \(5! = 120\) ways, but each cycle is counted twice (once each direction): 60 tours. Being sure means checking all 60.

Five more towns, each time

15 towns: under a minute. 20: two years. 25: ten million years. A computer a thousand times faster buys you about two more towns — no hardware upgrade fixes factorial growth.

Greedy: nearest neighbour from A

  1. 1 From A the nearest is E (2).
  2. 2 From E: B (4).
  3. 3 From B: D (2).
  4. 4 From D: F (6) beats C (8).
  5. 5 From F: C (6) — the only town left.
  6. 6 Return C → A: forced, and costs 10.
  7. ✓ Length \(2 + 4 + 2 + 6 + 6 + 10 =\) 30 km

What went wrong: the stranded town

  • C is far from everyone. Nearest neighbour keeps choosing closer towns, so C is left until last — and the trip home from C is the longest edge in the tour — the thick orange leg on the previous slide.
  • Every choice was locally best and never reconsidered. That is exactly what makes it greedy, and exactly why it can't see the final leg coming.
  • \(O(n^2)\): \(n\) steps, each scanning up to \(n\) towns. Fast, valid, no guarantee.
The fix is not "be greedier"

Building a better tour step by step needs foresight greedy doesn't have. Instead, take the finished tour and improve it — local search.

Improving it: one 2-opt move

Remove D–F (6) and C–A (10)…

…reconnect as D–C (8) and F–A (5)

  • 2-opt: delete two edges and reconnect the tour the only other way possible — equivalent to reversing a segment (here F, C becomes C, F).
  • Change: \((8 + 5) - (6 + 10) = -3\). New tour A → E → B → D → C → F → A, length 27 km — the optimum, checked against all 60 tours.

Hill climbing

Apply improving 2-opt moves until none is left. Here one move reached the optimum; on large instances it stops at a local optimum.

Simulated annealing

Also accept some worse moves, with probability falling as the temperature drops — to escape local optima. See T11.

The objective of the travelling salesman problem is to find the — which one?

Alowest-cost tree that connects each node in the graph
Blowest-cost paths that connect each pair of nodes in the graph
Clowest-cost cycle that traverses every node of the graph exactly once
Dlowest-cost cycle that traverses every edge of the graph exactly once
Name the distractors

A is a minimum spanning tree. B is all-pairs shortest paths. D is the Chinese postman / Euler circuit. Only C is a cycle through every node once.

Why is the decision version in NP?

Adapted from VCAA Algorithmics (HESS) Written Examination 2021, Section B Q8a

Question (2 marks)

The decision version of TSP asks whether there is a cycle from a source node, visiting every other node exactly once, with total weight less than \(X\). Explain why this problem is in NP.

Answer

A problem is in NP if a proposed solution can be verified in polynomial time. [1] Given a proposed tour, we check that it starts and ends at the source, that every node appears exactly once, that each consecutive pair is joined by an edge, and that the weights sum to less than \(X\) — all \(O(n)\) with an adjacency matrix, so polynomial. [1]

The common slip

"It's in NP because it can't be solved in polynomial time" earns nothing. NP is about checking a solution, not about how hard finding one is — every problem in P is in NP too.

What if someone solved TSP quickly?

Adapted from VCAA Algorithmics (HESS) Written Examination 2020, Section B Q12b

Question (2 marks)

Jane claims an algorithm that solves the travelling salesman problem on \(n\) vertices in at most \(n^3 + n^2\) steps. If she is correct, what are the consequences for all other NP-complete problems? Explain.

Answer

TSP (decision) is NP-complete, so every problem in NP can be reduced to it in polynomial time. [1] Reducing any NP-complete problem to TSP and then running Jane's \(O(n^3)\) algorithm solves it in polynomial time — so every NP-complete problem, and all of NP, would be solvable in polynomial time: P = NP. [1]

The word that earns the mark

Reduction. The consequence follows from NP-completeness — every NP problem reduces to TSP — not from TSP simply being "hard".

Check yourself

How many distinct tours does brute force check for 8 towns?

\((8 - 1)!/2 = 5040/2 = 2520\).

Run nearest neighbour on the six towns starting from D. Is it better or worse than from A?

D → B (2) → E (4) → A (2) → F (5) → C (6) → D (8): total 27 — the optimum, the same cycle as the 2-opt result. C is still last, but the leg home from C is now 8, not 10. Trying every starting town is a cheap improvement: \(n\) runs, \(O(n^3)\).

Why can't hill climbing with 2-opt guarantee the optimal tour?

It stops when no single 2-opt move improves the tour. That is a local optimum: a better tour may exist that needs several moves, some of them worsening, to reach.

Is "find the shortest path from A to F" NP-hard like TSP? Explain.

No. Shortest path is in P — Dijkstra solves it in \(O((V + E)\log V)\). TSP is hard because the route must visit every node exactly once.

One sentence to remember

TSP asks for the cheapest cycle through every node once; checking a tour is easy, finding the best one takes \((n-1)!/2\) tries by brute force, so in practice we build a greedy tour and improve it by local search.
