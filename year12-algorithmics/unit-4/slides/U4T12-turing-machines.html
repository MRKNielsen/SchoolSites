Turing Machines

Unit 4 AOS3 · Topic 12 of 17 — the machine invented to answer a question about mathematics

VCE Algorithmics (HESS) · Northcote High School

Where this came from

  1. 1 1900 — Hilbert's programme. David Hilbert proposes that all of mathematics could be placed on a complete, consistent, mechanical footing.
  2. 2 1928 — the Entscheidungsproblem. "Decision problem": is there a definite procedure that, given any mathematical statement, decides whether it is provable?
  3. 3 1931 — Gödel. Any consistent system rich enough for arithmetic contains true statements it cannot prove. Hilbert's completeness goal fails.
  4. 4 1936 — Turing. To answer the Entscheidungsproblem he must first define "definite procedure" precisely. He invents an abstract machine to do it — and then proves no such procedure exists.
The point worth holding on to

The Turing machine was not designed to build computers. It was designed to make the phrase "there is an algorithm for this" mathematically precise, so that its absence could be proved.

The four components

  • Tape — infinite in both directions, divided into cells, each holding one symbol from a finite alphabet (including a blank). This is the memory.
  • Head — sits over one cell; can read it, write to it, and move one cell left or right.
  • State register — holds the machine's current state, from a finite set.
  • Transition table — for each (state, symbol read) pair, gives what to write, which way to move, and the next state. This is the program.
Mapping to a real computer

The tape is memory; the state register is the program counter and CPU state; the transition table is the program. That last correspondence is the one exam questions ask for.

Reading a transition table

Each row is a state; each column a symbol that might be read. The cell says: write, move, go to state.

  • "In state A, reading a 1: write 1, move left, enter state B."
  • A dash means no transition defined — that combination never arises, or the machine jams.
  • Everything the machine will ever do is in this table. There is no other program.

Worked example — tracing a machine

Setup

Using the table above. Tape reads 1 0 1 0 1, head starts on the rightmost 1, state A.

  1. 1 State A, reads 1 → write 1, move left, state B.  Tape 1 0 1 0 1, head on the 0.
  2. 2 State B, reads 0 → write 0, move left, state B.  Head on the middle 1.
  3. 3 State B, reads 1 → write 1, move left, state A.  Head on the second 0.
  4. 4 State A, reads 0 → no transition — the machine jams.
  5. ✓ Tracing means keeping three things updated every step: tape, head position, state. Write all three in a table.
Exam technique

Draw a three-column table — step, tape (with the head marked), state — and fill a row per transition. Trying to hold it in your head is where errors come from.

Why such a primitive machine matters

  • It has no arithmetic, no variables, no arrays, no functions. It reads, writes, moves and changes state.
  • And yet: anything any computer can compute, a Turing machine can compute. It is slower — sometimes absurdly so — but not less capable.
  • A universal Turing machine takes the description of another machine on its tape and simulates it. That is a stored-program computer, described in 1936.
Why simplicity is the point

To prove something is impossible for all algorithms, you need a model simple enough to reason about mathematically and general enough to capture every algorithm. The Turing machine is deliberately both.

A common misreading

"Turing machines can only run simple algorithms" is false. Simple architecture, unlimited capability — the two are unrelated.

Exam focus

Which statement about Turing machines is correct?

Adapted from VCAA Algorithmics (HESS) Written Examination 2023, Section A Q19

One of these is true — which?

Ait is possible for a specific Turing machine to halt on all inputs
Bno specific Turing machine halts on all inputs
Call Turing machines fail to halt on some input
Dall Turing machines halt on at least one input
The move to make

Three of these are universal claims about every machine. A single counterexample kills each. Can you build a machine that always halts? One that never does?

Working it through

  1. 1 A is true. Trivial example: a machine whose start state immediately transitions to halt whatever it reads. It halts on every input.
  2. 2 B is false — contradicted directly by that same machine.
  3. 3 C is false — same counterexample again. Plenty of machines halt on everything.
  4. 4 D is false. A machine whose only transition is "write blank, move right, stay in the same state" runs forever on every input, halting on none.
  5. ✓ Answer: A.
The distinction being tested

The Halting Problem says no single algorithm can decide, for every machine and input, whether it halts. It emphatically does not say individual machines have unpredictable behaviour. Options B–D confuse the two.

Proving a computer is as powerful as a Turing machine

Adapted from VCAA Algorithmics (HESS) Written Examination 2022, Section A Q17

To show a computer is Turing-complete, you would — do which?

Ashow the computer can emulate a Turing machine
Bshow a Turing machine can emulate the computer
Cshow the computer can solve NP-complete problems
Dshow the computer can solve problems in both P and NP-complete
Reasoning

Turing-complete means "at least as powerful as a Turing machine". You establish that by showing the computer can do everything a Turing machine can — i.e. emulate it. Option B has the direction backwards; C and D are about tractability, an unrelated axis.

Elaboration — two axes again

Options C and D in that question are not merely wrong; they are wrong in an instructive way.

Why it matters

Turing-completeness says nothing about speed. A Turing machine is spectacularly slow and perfectly universal. Being able to solve NP-complete problems is a claim about efficiency, and belongs in the other column entirely.

Check yourself

Name the four components of a Turing machine, and say which corresponds to a program.

Tape (infinite memory), head (reads, writes, moves one cell), state register (current state from a finite set), and transition table. The transition table is the program — it fully determines the machine's behaviour.

Why did Turing invent this machine?

To make "definite procedure" mathematically precise, so that Hilbert's Entscheidungsproblem could be settled. Proving that no algorithm solves a problem requires a formal definition of what an algorithm is — the machine supplies it.

A student says Turing machines can only run very simple algorithms. Correct them.

The machine's architecture is simple, but its capability is not limited: anything computable by any computer is computable by a Turing machine. A universal Turing machine can even simulate any other machine given its description. Simplicity of mechanism was chosen for provability, not to restrict power.

Trace: state B, head reads 0, using the table on the earlier slide. What happens?

The cell for (B, 0) says 0, left, B — write 0 (leaving the cell unchanged), move the head one place left, and remain in state B. This is a scanning loop: the machine walks left over 0s without altering them.

A Turing machine is tape, head, state and transition table — a deliberately simple model that captures everything computable, invented so that impossibility could be proved.
