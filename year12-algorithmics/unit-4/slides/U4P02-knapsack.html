The 0-1 Knapsack Problem

Unit 4 AOS2 · Additional topic 2 of 4 — brute force, backtracking, greedy and dynamic programming on one problem

VCE Algorithmics (HESS) · Northcote High School

The problem

0-1 knapsack

Given \(n\) items, each with a size \(s_i\) and a value \(v_i\), and a knapsack of capacity \(C\): choose a subset of the items whose total size is at most \(C\) and whose total value is as large as possible.

  • "0-1" means each item is either taken whole (1) or left (0). No fractions, no second copies.
  • It models any budgeted selection: projects under a fixed budget, cargo under a weight limit, ads in a fixed-length break.

Answer

Brute force — try every subset

  • Each item is in or out, so there are \(2^n\) subsets. For each, add up its size and value: \(O(n)\).
  • Total: \(O(n \cdot 2^n)\). Always correct — and hopeless beyond a few dozen items.

Doubling per item

Adding one item doubles the work. That is the signature of exponential growth, and why knapsack sits with TSP and graph colouring as a standard intractable problem.

Organising the search as a tree

Each node is a set of items; a child adds one item with a larger number, so no set appears twice.

Backtracking — stop as soon as it can't work

Algorithm Explore(items, last, c, sizes, values):    If size(items) > c Do        Return                          // over capacity: backtrack    record items if value(items) is the best so far    Foreach i from last + 1 To n Do        Explore(items ∪ {i}, i, c, sizes, values)Call Explore({ }, 0, c, sizes, values)
  • Adding items can only make a set bigger, so once a set is over capacity every set below it is too — the whole subtree can be skipped.
  • Same worst case as brute force, \(O(2^n)\): if every item fits, nothing is pruned. The saving is real but not guaranteed.
Stronger pruning

Also backtrack when value so far + value of every remaining item cannot beat the best found. That is branch and bound.

  • Each rule is \(O(n \log n)\) — a sort, then one pass. None finds 15 here.
  • Ratio-greedy fails because taking item 2 then item 4 leaves 4 units of space that item 1 (size 5) cannot use. Whole items waste space.
Fractional vs 0-1

If items could be cut, ratio-greedy would be optimal — fill the leftover space with part of the next item. The 0-1 restriction is exactly what breaks it.

Dynamic programming — the recurrence

Let \(K(i, c)\) be the best value using only items \(1..i\) with capacity \(c\). Item \(i\) is either left out, or put in:

Recurrence

\[ K(i, c) = \begin{cases} K(i-1, c) & \text{if } s_i > c \\[4pt] \max\big(K(i-1, c),\; v_i + K(i-1, c - s_i)\big) & \text{otherwise} \end{cases} \]

with \(K(0, c) = 0\) for every \(c\).

  • Optimal substructure: the best packing that includes item \(i\) is item \(i\) plus the best packing of the rest into \(c - s_i\).
  • Overlapping subproblems: the same \(K(i, c)\) is needed by many larger subproblems — so store each one once in a table.

So is knapsack in P after all?

  • The table has \((n + 1)(C + 1)\) cells, each filled in \(O(1)\): the DP runs in \(O(nC)\).
  • That looks polynomial — but \(C\) is a number, written in about \(\log_2 C\) digits. Doubling the number of digits squares \(C\).
  • Measured against the size of the input, \(O(nC)\) is exponential. It is called pseudo-polynomial.
Small capacity

\(C = 1000\), \(n = 500\): half a million cells. DP is the right tool, and it is exact.

Huge capacity

\(C = 10^{15}\) (sizes in grams of cargo, cents of budget): the table is impossibly big. Back to backtracking or heuristics.

The exam point

The DP does not show P = NP. Knapsack stays NP-complete; DP is an exact method that is fast only when \(C\) is small.

Question (1 mark)

The algorithm backtracks whenever it reaches a node that is over the capacity of 10. Identify the nodes in the tree that are never searched.

Answer

Over capacity (orange): {1,3}, {2,3}, {1,2,3} and {1,2,4}. Each is reached, checked and abandoned. Their children are never searched (red): {1,3,4}, {2,3,4} and {1,2,3,4}. {1,2,4} has no children, so it prunes nothing.

Algorithm BuildTree(c, sizes, values):    root ← new node with items = { }    AddChildren(root, 0, sizes, values)    Return rootAlgorithm AddChildren(node, last, sizes, values):    Foreach i from last + 1 To length(sizes) Do        child ← node with items ∪ {i}, size + sizes[i], value + values[i]        add child as a child of node        AddChildren(child, i, sizes, values)
Where the marks are

Children add only later items (no duplicates) · size and value are accumulated · it recurses on each child · a correct starting call. Turning it into Rosa's backtracking version is one line: only recurse when child.size ≤ c.

Check yourself

Why is \(O(nC)\) not considered polynomial time?

Input size is measured in bits. \(C\) takes only about \(\log_2 C\) bits to write, so \(C\) itself is exponential in its own length — adding one digit to \(C\) multiplies the running time by ten.

Explain why backtracking can safely skip every node below an over-capacity node.

Children only add items, and sizes are positive, so every descendant is at least as large as its over-capacity ancestor. None can fit, so none can be a solution.

Give a two-item instance where best-ratio greedy fails badly.

Capacity 10. Item A: size 1, value 2 (ratio 2). Item B: size 10, value 10 (ratio 1). Greedy takes A, then B no longer fits: value 2. Optimum is B alone: value 10.

Why is the decision version of knapsack in NP?

A proposed subset is a certificate. Checking it means summing at most \(n\) sizes and \(n\) values and comparing with \(C\) and \(k\) — \(O(n)\), polynomial time.

One sentence to remember

Knapsack is NP-complete: brute force and backtracking are exponential, greedy is fast but not optimal, and the \(O(nC)\) DP is exact but only pseudo-polynomial.
